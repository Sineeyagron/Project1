# แผนภาพและพจนานุกรมข้อมูลสำหรับรายงาน

โฟลเดอร์นี้มีเอกสารประกอบรายงานโปรเจกต์ LabHub: Use Case Diagram, ER Diagram และ Data Dictionary

## ไฟล์ที่ใช้ใส่รายงาน

| ไฟล์ | เนื้อหา |
|---|---|
| `usecase-borrow-user` | Use Case ระบบยืม-คืน ส่วนผู้ใช้ |
| `usecase-borrow-staff` | Use Case ระบบยืม-คืน ส่วนผู้ดูแล (TA, ผู้ดูแลระบบ, ระบบตั้งเวลา) |
| `usecase-room` | Use Case ระบบห้องคอมพิวเตอร์ |
| `er-borrow-overview`, `er-room-overview` | ER ภาพรวม: ชื่อตาราง + ความสัมพันธ์ (ใส่ในเนื้อเรื่อง) |
| `er-borrow`, `er-room` | ER แบบละเอียด: PK, FK, คอลัมน์หลัก (ใส่ภาคผนวก หน้าแนวนอน) |
| `data-dictionary.docx` | พจนานุกรมข้อมูล 23 ตาราง ทุกคอลัมน์ |

รูปทุกรูปมี 2 แบบ: `.svg` คมทุกขนาด (แนะนำสำหรับ Word 365) · `.png` ใช้ได้ทุกโปรแกรม

Data Dictionary ใช้ฟอนต์ **TH Sarabun New** ถ้าเครื่องไม่มีฟอนต์นี้ ให้ติดตั้งก่อนเปิด ไม่งั้นตารางจะเพี้ยน

## วิธีแก้ไข (แบบง่าย — ใช้แบบนี้ก่อน)

**แก้ Data Dictionary** → ดับเบิลคลิก `data-dictionary.docx` เปิดใน Word แล้วพิมพ์แก้ได้เลย

**แก้รูป** →
1. เข้าเว็บ [app.diagrams.net](https://app.diagrams.net) (draw.io ฟรี ไม่ต้องสมัคร)
2. ลากไฟล์ `.svg` ของรูปที่จะแก้ เข้าไปวางในหน้าเว็บ
3. คลิกข้อความหรือกล่องเพื่อแก้/ย้ายได้เหมือน PowerPoint
4. เสร็จแล้ว File → Export as → PNG แล้วเอารูปนั้นไปใส่รายงาน

แค่นี้พอ ส่วนข้างล่างเป็นวิธีสำหรับคนที่เขียนโค้ดเป็น ไม่ต้องอ่านก็ได้

### สำหรับคนเขียนโค้ด: แก้ต้นฉบับแล้วสั่งสร้างใหม่ (ทุกรูปหน้าตาเหมือนกันเสมอ)

หมายเหตุ: ถ้าใช้วิธีนี้ รูปที่เคยแก้มือด้วย draw.io จะถูกสร้างใหม่ทับ

ต้องมี: [Node.js](https://nodejs.org) 18 ขึ้นไป, Google Chrome หรือ Microsoft Edge, อินเทอร์เน็ต (ตอนสร้าง ER โหลดตัววาดจากเน็ต)

ครั้งแรกครั้งเดียว เปิด Terminal ที่โฟลเดอร์นี้ (`docs/diagrams`) แล้วรัน:

```bash
npm install
```

จากนั้นแก้ไฟล์ใน `src/` ตามตาราง แล้วรันคำสั่งที่ตรงกัน:

| อยากแก้ | แก้ไฟล์ | รันคำสั่ง |
|---|---|---|
| Use Case (เพิ่ม/ลบ/เปลี่ยนชื่อวงรี, ผู้กระทำ, «include») | `src/usecase.js` (ส่วนข้อมูลด้านล่างของไฟล์) | `npm run usecase` |
| ER (ตาราง, คอลัมน์, เส้นความสัมพันธ์) | `src/er-*.mmd` | `npm run er` |
| Data Dictionary (คำอธิบาย, คอลัมน์) | `src/data-dictionary.js` (ตัวแปร `GROUPS`) | `npm run dd` |
| ทุกอย่าง | — | `npm run build` |

รูปใหม่จะไปแทนไฟล์เดิมในโฟลเดอร์นี้

ถ้าขึ้นว่า "ไม่เจอ Chrome/Edge" ให้บอกตำแหน่งเอง เช่น:

```bash
CHROME="C:/path/to/chrome.exe" npm run er
```

#### แก้ Use Case

ใน `src/usecase.js` แต่ละวงรีเขียนแบบ `["รหัส", "ข้อความในวงรี"]` อยู่ในกลุ่มของผู้กระทำ (ผู้ใช้ / TA / ผู้ดูแลระบบ)

- **เพิ่มวงรี**: เพิ่มบรรทัดในกลุ่มที่ต้องการ ขนาดวงรีปรับตามข้อความให้เอง
- **«include» / «extend»**: วงรีปลายทางใส่ใน `extras` ส่วนเส้นใส่ใน `deps` เช่น `["borrow", "photo", "include"]`

กติกาการตั้งชื่อ: 1 วงรี = 1 เป้าหมายของผู้ใช้ ขึ้นต้นด้วยกริยา (เช่น "ขอยืมอุปกรณ์") ไม่ใช้ "/" รวมหลายเรื่อง และกฎภายในระบบ (เช่น จำกัด 5 ครั้งต่อวัน) ไม่ใช่ use case

#### แก้ ER

ไฟล์ `.mmd` เป็นภาษา Mermaid (erDiagram) อยากลองก่อนสร้างจริง วางโค้ดใน [mermaid.live](https://mermaid.live) เพื่อดูผลทันที

- เส้นความสัมพันธ์: `A ||--o{ B : "ป้าย"` อ่านว่า A 1 แถว มี B ได้ 0 ถึงหลายแถว
- สัญลักษณ์ฝั่งตารางแม่: `||` = คอลัมน์ FK ห้ามว่าง (not null) · `|o` = ว่างได้ (null)
- `..` แทน `--` = เส้นประ (อ้างถึงกันแต่ฐานข้อมูลไม่ได้ตั้ง FK)

## สำคัญ: ต้องตรงกับฐานข้อมูลจริง

ทุกอย่างในโฟลเดอร์นี้ตรงกับฐานข้อมูลจริงใน Supabase ณ 28 ต.ค. 2569 (ตรวจทุกคอลัมน์และทุก FK แล้ว) ถ้ามีการเพิ่ม/แก้ตารางในฐานข้อมูลภายหลัง (ไฟล์ใหม่ใน `supabase/migrations/`) ต้องแก้ทั้ง ER และ Data Dictionary ตาม

ดูโครงสร้างจริงได้ที่ Supabase Dashboard → Table Editor หรือรันใน SQL Editor:

```sql
select table_name, column_name, data_type, is_nullable, column_default
from information_schema.columns where table_schema = 'public'
order by table_name, ordinal_position;
```
