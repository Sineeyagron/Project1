## 0. กติกาที่ต้องรักษา (จาก SYSTEM_OVERVIEW §11 — ห้ามละเมิด)

- ระบบยืม-คืน กับ ระบบห้องคอม **แยกกันเด็ดขาด** (ไม่ import ไฟล์/ตารางข้ามกัน) — ฟีเจอร์ทั้งหมดในเอกสารนี้อยู่ฝั่ง **ระบบยืม-คืน**

- **ประหยัด Supabase ฟรี (Disk IO)**: ห้ามเพิ่ม polling ฝั่งแอป ใช้ Realtime Broadcast เดิม · ห้ามสร้าง pg_cron ใหม่ถ้ารวมกับงานเดิมได้
- migration ใหม่ตั้งชื่อต่อจากไฟล์ล่าสุดใน `supabase/migrations/` (ล่าสุด `20261006100000_profile_student_id.sql`)

## F1. ป๊อปอัปยืนยัน + กฎการยืม-คืน

### ข้อสรุป (ล็อกแล้ว)
- เด้ง **ทุกครั้ง** ที่กด ขอยืม / ขอคืน / ขอยืมต่อ (หน้า `app/scan.tsx`) — เป็นขั้นยืนยันสุดท้ายก่อนส่ง RPC
- กฎ **ชุดเดียวกัน** ทั้ง 3 แบบ · ต้องติ๊ก "ฉันอ่านและยอมรับกฎการยืม-คืนแล้ว" ก่อน ปุ่มยืนยันถึงกดได้ (ไม่จำค่าติ๊กข้ามครั้ง)
- **Admin แก้ข้อความกฎได้** ในหน้าตั้งค่าระบบ (`app/admin/settings.tsx`) — เพิ่ม/แก้/ลบ/เรียงข้อได้ · ข้อความจริงค่อยแก้ทีหลัง ใช้ร่างด้านล่างเป็นค่าเริ่มต้น
- **กฎใหม่บังคับใน DB**: ขอยืมต่อได้ถึง **วันครบกำหนด (รวมวันครบกำหนด)** — เกินกำหนดแล้ว (`due_date < วันนี้ไทย`) ห้ามยืมต่อ

### กฎตั้งต้น (ตัวแปรใน `{}` แทนด้วยค่าจาก app_settings ตอนแสดงผล)
1. ยืมพร้อมกันได้สูงสุด {max} ชิ้น (นับรวมคำขอที่รออนุมัติ)
2. เลือกระยะยืมได้ {days} วัน
3. ต้องถ่ายรูปและระบุสภาพทุกครั้งที่ยืมและคืน
4. คำขอรอผู้ดูแลอนุมัติภายใน {expiry} นาที ไม่มีคนตอบ: ขอยืม = หมดอายุ / ขอคืน = คืนอัตโนมัติ (ผู้ดูแลตรวจย้อนหลัง)
5. คืนแล้วของชำรุด อาจมีค่าเสียหาย
6. ยืมต่อได้ 1 ครั้ง ต้องขอภายในวันครบกำหนด วันที่เพิ่มนับต่อจากวันครบกำหนดเดิม

`{max}` = `max_active_borrows`, `{days}` = `borrow_day_options` ต่อด้วย " / ", `{expiry}` = `request_expiry_minutes`

### Backend
- `app_settings` เพิ่ม key `borrow_rules` = jsonb array ของข้อความ (insert ค่าเริ่มต้นข้างบน) — ตาราง app_settings อ่านได้ทุกคนที่ล็อกอินอยู่แล้ว, เขียนได้เฉพาะ admin ตาม policy เดิม (ตรวจ policy อีกครั้ง)
- แก้ `request_renew` (อยู่ใน `20261003100000_phase3_rpc.sql`) ผ่าน migration ใหม่ `create or replace`: เพิ่มเช็ก `if rec.due_date < public._bkk_today() then raise exception 'เกินกำหนดคืนแล้ว ยืมต่อไม่ได้ กรุณานำมาคืน'`
- (ไม่บังคับใน DB ว่าติ๊กยอมรับ — เป็น UX ฝั่งแอป)

### UI
- Component ใหม่ใช้ร่วม เช่น `components/ConfirmRulesSheet.tsx` (BottomSheet เดิม): หัวข้อ "ยืนยันการขอยืม/ขอคืน/ขอยืมต่อ", การ์ดสรุปของ (ชื่อ/รหัส), แถวสรุป (ระยะยืม + ครบกำหนด / สภาพ+รูปแล้ว / สำหรับยืมต่อ: ครบกำหนดเดิม (ขีดฆ่า) → ใหม่), กล่องกฎเลื่อนได้ (สูงสุด ~250px), checkbox, ปุ่ม [ยกเลิก] [ยืนยันส่งคำขอ…] (เทาจนติ๊ก)
- หน้า scan: ถ้าเกินกำหนดแล้ว ซ่อน/ปิดปุ่มยืมต่อ + ข้อความ "เกินกำหนดแล้ว กรุณานำมาคืน" (DB ยังเป็นด่านจริง)
- หน้าโปรไฟล์ (`app/profile.tsx` การ์ด "กติกาการยืม") เปลี่ยนไปอ่านจาก `borrow_rules` ชุดเดียวกัน
- หน้าตั้งค่า: การ์ด "กฎการยืม-คืน" — แต่ละข้อเป็นช่องข้อความ + ปุ่มลบ, ปุ่ม "+ เพิ่มข้อ", ปุ่ม "บันทึกกฎ", คำอธิบายตัวแปร `{max}` `{days}` `{expiry}`

### เกณฑ์ผ่าน
- [ ] กดขอยืม/คืน/ยืมต่อ → เห็นป๊อปอัป ไม่ติ๊ก = ส่งไม่ได้ ติ๊กแล้วส่งได้
- [ ] Admin แก้กฎ → นศ. เห็นข้อความใหม่ทั้งในป๊อปอัปและหน้าโปรไฟล์
- [ ] TA/นศ. แก้ `borrow_rules` ไม่ได้ (RLS)
- [ ] ยืมต่อในวันครบกำหนด = ได้ / วันถัดไป = RPC ปฏิเสธ

## F3. ประวัติแบบแอปธนาคาร (นศ. + Admin)

### ข้อสรุป (ล็อกแล้ว)
- ทำ **ทั้ง 2 หน้า**: นศ. `app/borrow.tsx` (ส่วนรายการ) และ Admin `app/admin/history.tsx`
- จัดกลุ่มตาม **วัน** หัวกลุ่มรูปแบบ `09/10/2569` (พ.ศ., วันนี้ = "วันนี้ · 10/10/2569") + ชื่อวันด้านขวา
- แต่ละรายการ: **เวลา HH:mm** · ไอคอน+ชนิด · ชื่อของ · รายละเอียดบรรทัดล่าง · ใหม่สุดอยู่บน

### ชนิดเหตุการณ์ (ไอคอน/สี)
| ชนิด | แหล่งข้อมูล | เวลา | รายละเอียด |
|---|---|---|---|
| ↗ ยืมออก (ฟ้า) | `borrow_records.borrow_date` | borrow_date | ครบกำหนด dd/mm/yyyy · ยืม N วัน (+Admin: อนุมัติโดย) |
| ↙ คืนเข้า (เขียว) | `borrow_records.return_date` | return_date | สภาพปกติ / ชำรุด + ค่าเสียหาย (ส้ม) / คืนอัตโนมัติ (รอตรวจย้อนหลัง) |
| ↻ ยืมต่อ (ม่วง) | `borrow_requests` kind=renew, status=approved | decided_at | ครบกำหนดใหม่ (เดิม …) |
| ✕ ถูกปฏิเสธ (แดง) | `borrow_requests` status=declined | decided_at | เหตุผล: decision_note |
| ⏱ หมดอายุ (เทา) | `borrow_requests` status=expired | expires_at/decided_at | ไม่มีผู้ดูแลตอบภายใน N นาที |

- ⚠️ **ยังไม่ล็อก**: จะโชว์ "ถูกปฏิเสธ/หมดอายุ" ด้วยไหม — mockup ใส่ไว้ใต้ตัวกรอง "อื่น ๆ" (ทำให้ซ่อน/แสดงง่ายด้วย flag เดียว)
- ⚠️ ตรวจชนิดคอลัมน์ `borrow_records.borrow_date / return_date` ก่อน (RPC ใส่ `now()` → น่าจะ timestamptz แต่ตารางนี้ไม่ได้สร้างใน migrations — เช็กใน DB จริง) · `due_date` เป็น date ล้วน (ดูคอมเมนต์ใน borrow.tsx เรื่อง timezone)
- แสดงเวลาเป็นเวลาไทย (Asia/Bangkok) เสมอ

### UI
- นศ.: หัว "ประวัติการยืม" + "ยืมอยู่ N ชิ้น · ยืมได้อีก M ชิ้น", ตัวกรองชิป [ทั้งหมด][ยืมออก][คืนเข้า][อื่น ๆ] · ส่วน "คำขอที่รออนุมัติ" เดิมคงไว้ด้านบน
- Admin: ช่องค้นหา (ชื่อ / รหัส นศ. / อุปกรณ์), ชิป [ทั้งหมด][ยืมออก][คืนเข้า][เกินกำหนด][อื่น ๆ], หัวกลุ่มวันมีจำนวนรายการ, แต่ละแถวมีบรรทัด "ชื่อ · รหัส นศ." ผ่าน `who()` ใน `lib/people.ts`
- แต่ละกลุ่มวัน = พื้นขาวมุมโค้ง 1 ก้อน แถวคั่นเส้นบาง (ไม่ใช่การ์ดต่อแถว)
- ทำ helper จัดกลุ่ม/แปลงเหตุการณ์เป็นตรรกะล้วนใน `lib/` (เช่น `lib/timeline.ts`) ใช้ร่วม 2 หน้า

### เกณฑ์ผ่าน
- [ ] ยืม→คืน ในวันเดียว เห็น 2 แถวในกลุ่มวันเดียวกัน เวลาถูก (ไทย)
- [ ] ข้ามวันแสดงหัววันใหม่ · ตัวกรองทำงาน · ค้นหา (Admin) ทำงาน
- [ ] ไม่เพิ่มจำนวน query จนช้ากว่าเดิมชัดเจน (ดึงเป็นช่วง/จำกัดจำนวน เช่น 60 วันล่าสุด + โหลดเพิ่ม)

## F4. สถานะ "มีผู้ดูแลอยู่ที่ IoT Lab ไหม" (เช็กอิน/เช็กเอาท์)

### ข้อสรุป (ล็อกแล้ว)
- **TA และ Admin** กดปุ่มเดียว **เช็กอิน / เช็กเอาท์** (ไม่ต้องเลือกเวลา) — การกดให้ตรงความจริงเป็นความรับผิดชอบของผู้ดูแล
- นศ. เห็น **บทบาท + ชื่อ** ทุกคนที่อยู่: "TA [ชื่อ] · เช็กอิน 13:05"
- กันลืม: **ทุกวัน 17:00 (เวลาไทย) เช็กเอาท์ทุกคนอัตโนมัติ** ไม่มี UI เพิ่ม
- ใช้คำว่า "อยู่ที่ IoT Lab" ไม่ใช่ "ออนไลน์" (เปิดแอป ≠ อยู่ห้อง) · ไม่ใช้การตรวจจับว่าเปิดแอป
- 💡 ไอเดียอนาคต (ยังไม่ทำ): ตารางเวรประจำสัปดาห์

### Backend (ข้อเสนอ — ปรับได้)
- ตารางใหม่ `staff_presence(user_id uuid pk → profiles, location_id → borrow_locations, checked_in_at timestamptz)` — มีแถว = อยู่, ไม่มี = ไม่อยู่ (ลบแถวตอนเช็กเอาท์) · RLS: อ่านได้ทุกคนที่ล็อกอิน, เขียนผ่าน RPC เท่านั้น
- RPC `staff_check_in()` / `staff_check_out()` (security definer, ต้อง `is_staff()`)
- เช็กเอาท์ 17:00: เพิ่ม cron รายวัน `0 10 * * *` (10:00 UTC = 17:00 ไทย) หรือรวมกับงานรายวันที่มี — รันวันละครั้ง ภาระต่ำมาก
- Realtime: ตอนเช็กอิน/เอาท์ broadcast สัญญาณให้แอป นศ. รีโหลดแถบ (ต้องมีช่องที่ นศ. ทุกคนฟังได้ — ช่อง `user:<id>`/`staff` เดิมไม่พอ → เพิ่มช่องใหม่ของระบบยืม เช่น `lab` พร้อม policy ใน `realtime.messages` แบบเดียวกับ `20261004120000_realtime_broadcast.sql`) **ห้ามใช้ช่อง `room` ของระบบห้อง**

### UI
- หน้าแรก นศ. (`app/home.tsx`) ใต้คำทักทาย เหนือการ์ด "สแกนยืม/คืน":
  - มีคน: การ์ดเขียวอ่อน "● มีผู้ดูแลอยู่ที่ IoT Lab ตอนนี้" + รายชื่อ (บทบาท ชื่อ · เช็กอิน HH:mm) + "ไปที่ห้องแล้วให้ผู้ดูแลเปิดตู้ จากนั้นสแกน QR ที่อุปกรณ์"
  - ไม่มีคน: การ์ดขาว จุดเทา "ตอนนี้ไม่มีผู้ดูแลอยู่ที่ IoT Lab" + "อยากยืมของ? ส่งคำขอนัดรับไว้ได้…" + ปุ่ม "ขอยืมแบบนัดรับ" (ก่อนมี F2 ซ่อนปุ่มนี้)
  - หน้าแรกแชร์กับระบบห้อง → แยกเป็น component ของระบบยืม (เช่น `components/StaffPresenceBanner.tsx`) ห้ามไปปนกับโค้ดระบบห้อง
- แดชบอร์ด Admin/TA (`app/admin/home.tsx`) การ์ดบนสุด: สถานะของตัวเอง + ปุ่ม [เช็กอิน อยู่ที่ IoT Lab] (primary) / [เช็กเอาท์ (ออกจากห้อง)] (ขอบ ตัวแดง) + "ตอนนี้อยู่ที่ห้อง" รายชื่อ + "ลืมเช็กเอาท์ ระบบจะเช็กเอาท์ให้อัตโนมัติ 17:00"

### เกณฑ์ผ่าน
- [ ] TA เช็กอิน → หน้าแรก นศ. ที่เปิดอยู่เปลี่ยนเป็นเขียวเองภายในไม่กี่วินาที (ไม่ต้องรีเฟรช)
- [ ] นศ. เรียก RPC เช็กอินไม่ได้ · 17:00 ทุกคนหลุดอัตโนมัติ

## F2. ขอยืมแบบนัดรับ

### ปัญหาที่แก้
ห้องเปิด นศ. อยู่หน้าตู้ แต่ของอยู่ในตู้ล็อก และ TA/Admin ไม่มีใครว่างเปิดให้ → ตอนนี้ยืมไม่ได้ (ต้องสแกน QR ที่ตัวของ + คำขอหมดอายุใน 30 นาที)

### ข้อสรุป (ล็อกแล้ว)
- เพิ่มทาง **"ขอยืมแบบนัดรับ"** — **สแกนยืมแบบเดิมยังอยู่ครบ** (ใช้ตอนผู้ดูแลอยู่)
- นศ. เลือก **รุ่น** จากหน้าอุปกรณ์ (`app/equipment.tsx`, รุ่น = `items.item_prefix` ตามที่หน้านี้จัดกลุ่มอยู่แล้ว) ไม่ต้องสแกน + เลือกระยะยืม 3/5/7 + หมายเหตุ (ไม่บังคับ เช่น "สะดวกช่วงบ่าย") + ยอมรับกฎ (F1)
- **ผู้ดูแล (TA หรือ Admin) เป็นคนกำหนดวัน-เวลานัดรับ** — มีปุ่มลัด [ตอนนี้] [อีก 10 นาที] [อีก 30 นาที] [เลือกเวลา (วันที่+เวลา)] · ปฏิเสธได้ (ต้องมีเหตุผล เหมือน decide_request)
- ผู้ดูแล **ไม่ตอบภายใน 12 ชั่วโมง** = คำขอหมดอายุ
- ยืนยันนัดแล้ว → **กันของรุ่นนั้นไว้ 1 ชิ้น** (นับรวมในโควตา `max_active_borrows`) + แจ้งเตือน นศ. "มารับได้ dd/mm/yyyy HH:mm · นัดโดย [ชื่อ]"
- วันนัด: ผู้ดูแลเปิดตู้ หยิบชิ้นไหนก็ได้ของรุ่นนั้น → **นศ. สแกน QR ชิ้นที่ได้ + ถ่ายรูป/สภาพ = บันทึกยืมทันที ไม่ต้องอนุมัติซ้ำ** · วันครบกำหนด = วันรับ + ระยะยืม
- ไม่มาตามนัด: **เลยเวลานัด 10 นาที = ยกเลิกอัตโนมัติ** + ผู้ดูแลกด "นศ. ไม่มา · ยกเลิกนัด" เองได้ · นศ. ยกเลิกคำขอ/นัดของตัวเองได้
- การหมดอายุ 12 ชม. และยกเลิกเมื่อเลยนัด 10 นาที → **รวมใน cron `expire-borrow-requests` เดิม** (ไม่สร้าง cron ใหม่) — ยกเลิกจริงช้ากว่านั้นได้ เจ้าของยอมรับ เน้นประหยัด
- ⚠️ ไม่มี push notification (Expo Go) — แจ้งเตือนทันทีเฉพาะตอนเปิดแอปอยู่ (ใช้ Realtime ช่อง `user:<id>` / `staff` เดิม)

### Backend (ข้อเสนอ — ให้ผู้ลงมือออกแบบรายละเอียดเอง แต่ต้องได้พฤติกรรมตามข้อสรุป)
- ตารางใหม่ เช่น `pickup_requests`: user_id, item_prefix (รุ่น), days, note, status (`pending` → `scheduled` → `picked_up` | `declined` | `expired` | `cancelled` | `no_show`), pickup_at timestamptz, scheduled_by, decision_note, picked_item_id, borrow_record_id, created_at, expires_at (= created_at + 12 ชม.)
- RPC: `request_pickup(p_prefix, p_days, p_note)` (เช็กโควตา + มีของว่างหลังหักที่กันไว้), `schedule_pickup(p_id, p_pickup_at)` / `decline_pickup(p_id, p_note)` (staff, TA ห้ามจัดการคำขอของตัวเอง แบบเดียวกับ `borrow_requests_no_self_decide`), `cancel_pickup(p_id)` (เจ้าของหรือ staff), `claim_pickup(p_item_id, p_condition, p_note, p_photo_path)` (นศ. สแกนตอนรับ: ต้องมีนัด scheduled ของรุ่นนี้ ณ เวลานั้น → สร้าง `borrow_records` + ของ = borrowed + ปิดนัด; ใช้การตรวจรูปแบบเดียวกับ `request_borrow` — รูปในโฟลเดอร์ตัวเอง ห้ามซ้ำ)
- **กันของซ้อน (สำคัญ)**: จำนวนว่างของรุ่น = ชิ้น `available` − นัด `scheduled` ที่ยังไม่รับของรุ่นนั้น → `request_borrow` เดิม (สแกนยืมปกติ) ต้องเช็กด้วย: ถ้าว่างหลังหัก = 0 ให้ปฏิเสธ "ชิ้นที่เหลือถูกกันไว้ให้คนที่นัดรับแล้ว" (ยกเว้นคนที่สแกนคือคนที่มีนัดรุ่นนั้น → ไป `claim_pickup`)
- `scan_lookup` เพิ่มสถานะให้แอปรู้ว่า "คุณมีนัดรับรุ่นนี้" เพื่อเปลี่ยนปุ่มเป็น "ยืนยันรับของตามนัด"
- โควตา `max_active_borrows` นับรวม pickup ที่ pending/scheduled
- แจ้งเตือน: มีคำขอใหม่ → staff · นัดแล้ว/ปฏิเสธ/หมดอายุ/ยกเลิก/no-show → นศ.
